## 1. Главный цикл сервера — `start_server()`

### Описание

`start_server()` — точка входа в сетевую часть программы. Функция выполняется в `server.c`.
Создаёт прослушивающий TCP-сокет, привязывает его к адресу и порту из конфигурации, после чего входит в **бесконечный цикл** обработки входящих соединений.

Сервер **однопоточный**: каждое соединение обрабатывается полностью до вызова `close()`, после чего начинается ожидание следующего. Это упрощает код, но означает, что одновременно может работать только один клиент.

### Шаги алгоритма

| # | Действие | Системный вызов / функция |
|---|----------|--------------------------|
| 1 | Создать TCP-сокет | `socket(AF_INET, SOCK_STREAM, 0)` |
| 2 | Разрешить повторное использование порта | `setsockopt(SO_REUSEADDR)` |
| 3 | Привязать сокет к IP и порту | `bind()` |
| 4 | Перевести в режим прослушивания | `listen(backlog=5)` |
| 5 | Создать директорию загрузки, если не существует | `stat()` + `mkdir()` |
| 6 | Запись в журнал: сервер запущен | `log_msg("INFO", ...)` |
| 7 | Игнорировать сигнал SIGPIPE | `signal(SIGPIPE, SIG_IGN)` |
| 8 | **Цикл**: принять соединение | `accept()` |
| 9 | Получить IP-адрес клиента | `getpeername()` + `inet_ntop()` |
| 10 | Установить тайм-аут на сокет | `setsockopt(SO_RCVTIMEO, SO_SNDTIMEO)` |
| 11 | Прочитать заголовки HTTP | `recv(cl, buf, MAX_HEADER_SIZE)` |
| 12 | Распарсить метод, путь, заголовки | `parse_http_headers()` |
| 13 | Обработать запрос (маршрутизация) | → алгоритм 2 |
| 14 | Закрыть соединение, вернуться к шагу 8 | `close(cl)` |

## 2. Маршрутизация и обработка запроса

### Описание

После парсинга заголовков сервер определяет, что делать с запросом, по методу (`GET`/`POST`) и пути (`/`, `/upload`). Порядок проверок важен: сначала GET — он не требует авторизации для отдачи формы; затем POST — с проверкой авторизации.

### Шаги алгоритма

| # | Условие / действие | Результат |
|---|-------------------|-----------|
| 1 | `method == GET && path == /` | → 200 + HTML-форма |
| 2 | `method == GET && path != /` | → 404 Not Found |
| 3 | `method == POST && path != /upload` | → 404 Not Found |
| 4 | `auth_enabled && !check_auth()` | → 401 Unauthorized |
| 5 | Нет `\r\n\r\n` в буфере | → 400 Bad Request |
| 6 | Нет `boundary=` в Content-Type | → 400 Bad Request |
| 7 | `fopen(upload.bin)` не удалось | → 500 Internal Server Error |
| 8 | `parse_multipart()` вернул < 0 | → `unlink(file)` + 400 Bad Request |
| 9 | Успех | → `rename(upload.bin → filename)` + 200 OK |

## 3. Парсинг тела запроса — `parse_multipart()`

### Описание

Функция в `multipart.c` получает всё тело `multipart/form-data` запроса, извлекает из него данные файла и записывает их на диск.

**Ключевая особенность**: тело запроса — бинарные данные, поэтому функция работает через `memcpy`/`recv` с явными длинами, а не через строковые функции, предполагающие нулевой терминатор.

### Шаги алгоритма

| # | Действие | Пояснение |
|---|----------|-----------|
| 1 | Проверка `total` | 0 или > MAX_BODY_SIZE (50 МБ) → ошибка |
| 2 | `malloc(total + 1)` | Выделить буфер под всё тело |
| 3 | `memcpy` начальных данных | Первый кусок уже прочитан в `server.c` вместе с заголовками |
| 4 | Цикл `recv()` | Дочитать оставшиеся байты до `Content-Length` |
| 5 | `strstr("--" + boundary)` | Найти начало части |
| 6 | `strstr("\r\n\r\n")` | Пропустить заголовки части |
| 7 | Извлечь `filename=` | Из `Content-Disposition` заголовка части |
| 8 | `strstr("--" + boundary)` | Найти конец данных файла |
| 9 | Обрезать `\r\n` | Браузер добавляет `\r\n` перед финальным boundary |
| 10 | `fwrite(data, len, out)` | Записать данные файла |
| 11 | `free(buf)` | Освободить буфер |

## 4. Проверка авторизации — `check_auth()` / `b64()`

### Описание

Реализована в `auth.c`. Принимает строку заголовка `Authorization` и конфигурацию, возвращает 1 (успех) или 0 (отказ).

HTTP Basic Auth передаёт логин и пароль в Base64: `Basic YWRtaW46YWRtaW4=`.
Base64 — не шифрование, а кодирование: каждые 3 байта → 4 ASCII-символа из алфавита A–Z, a–z, 0–9, +, /.

**Вспомогательная функция `b64()`** реализует декодер за один проход по строке, накапливая биты в аккумуляторе `v` и извлекая байты при накоплении ≥ 8 бит.

### Шаги алгоритма

| # | Действие |
|---|----------|
| 1 | Проверить наличие префикса `"Basic "` |
| 2 | Взять подстроку после `"Basic "` |
| 3 | Декодировать Base64 → `decoded[]` |
| 4 | Собрать ожидаемую строку: `username:password` из конфига |
| 5 | `strcmp(decoded, expected)` → 0 означает успех |

### Алгоритм Base64-декодирования (`b64`)

Каждый символ Base64 несёт 6 бит. Функция `idx(c)` переводит ASCII-символ в 6-битное число:

| Символы | Значения |
|---------|----------|
| A–Z | 0–25 |
| a–z | 26–51 |
| 0–9 | 52–61 |
| + | 62 |
| / | 63 |

Алгоритм накопления: `v = (v << 6) + idx(c)`, `bits += 6`.
Когда `bits >= 8`: извлечь байт `(v >> (bits-8)) & 0xFF`, `bits -= 8`.

### Блок-схема

```
    ┌──────────────────────────────────┐
    │           НАЧАЛО                 │
    │ check_auth(header, config)       │
    └───────────────┬──────────────────┘
                    │
             ┌──────▼────────────────┐
             │ strncmp(header,       │
             │ "Basic ", 6) == 0?    │──Нет──► return 0
             └──────┬────────────────┘
                   Да
                    │
    ┌───────────────▼──────────────────┐
    │ token = header + 6               │
    │ (Base64-строка после "Basic ")   │
    └───────────────┬──────────────────┘
                    │
    ┌───────────────▼──────────────────┐
    │  b64(token, decoded):            │
    │  v = 0, bits = -8, len = 0       │
    └───────────────┬──────────────────┘
                    │
             ┌──────▼──────────┐
        ┌───►│ *token != '\0'  │──Нет──► decoded готов
        │    │ && idx(*token)  │
        │    │ >= 0?           │
        │    └──┬──────────────┘
        │      Да
        │       │
        │    ┌──▼───────────────────────┐
        │    │ d = idx(*token)          │
        │    │ v = (v << 6) + d        │
        │    │ bits += 6               │
        │    └──┬───────────────────────┘
        │       │
        │    ┌──▼──────┐
        │    │bits >= 0│──Да──► decoded[len++] = (v>>bits)&0xFF
        │    │ ?       │        bits -= 8
        │    └──┬──────┘
        │      Нет
        │       │
        │    token++
        └────┘ (следующий символ)

    decoded готов:
                    │
    ┌───────────────▼──────────────────┐
    │ snprintf(expected, sizeof,       │
    │   "%s:%s", config->username,     │
    │   config->password)              │
    └───────────────┬──────────────────┘
                    │
             ┌──────▼───────────────────┐
             │ strcmp(decoded,          │
             │ expected) == 0?          │
             └──┬──────────┬────────────┘
               Да          Нет
                │            │
           return 1      return 0
          (успех)        (отказ)
```

## 5. Загрузка конфигурации — `load_config()`

### Описание

Реализована в `config.c`. Читает текстовый конфигурационный файл формата `ключ=значение` (по одному на строку). Сначала вызывается `default_config()`, заполняющая все поля безопасными значениями по умолчанию — это гарантирует, что отсутствующие в файле параметры получат рабочие значения.

**Формат файла:**
```
address=0.0.0.0
port=8080
upload_dir=/srv/uploads
username=admin
password=secret
auth_enabled=true
```

Строки без `=` и пустые строки молча пропускаются. Неизвестные ключи также игнорируются — это позволяет добавлять комментарии (`# comment`) без изменения парсера (строка `# comment` не содержит `=` в нужном месте).

### Шаги алгоритма

| # | Действие |
|---|----------|
| 1 | `default_config(cfg)` — заполнить значениями по умолчанию |
| 2 | `fopen(path, "r")` — открыть файл |
| 3 | Если файл не найден → вернуть -1 (конфиг по умолчанию уже установлен) |
| 4 | `fgets(line, 256, f)` — читать строку |
| 5 | `sscanf(line, "%63[^=]=%127s", key, val)` — разобрать пару |
| 6 | Если разобрано != 2 → к шагу 4 |
| 7 | Сравнить `key` с известными полями, присвоить значение |
| 8 | Повторить с шага 4 |
| 9 | `fclose(f)` → вернуть 0 |

```
    │ pass=admin, auth_enabled=true    │

                    │

    │ f = fopen(path, "r")             │
    └───────────────┬──────────────────┘
                    │
             ┌──────▼──────┐
             │ f == NULL?  │──Да──► return -1
             └──────┬──────┘
                   Нет

        │    │ вернул строку?        │──Нет──► fclose(f); return 0
        │    └──────┬────────────────┘
        │          Да
        │           │
        │    ┌──────▼────────────────────────┐
        │    │ sscanf(line,                  │
        │    │ "%63[^=]=%127s", key, val)    │
        │    └──────┬────────────────────────┘
        │           │
        │    ┌──────▼──────────┐
        │    │ Разобрано       │
        │    │ 2 поля?         │──Нет──────────────────┐
        │    └──────┬──────────┘                       │
        │          Да                                   │
        │           │                                   │
        │    ┌──────▼────────────────────────┐         │
        │    │ key == "address"    → cfg.address = val │
        │    │ key == "port"       → cfg.port = atoi() │
        │    │ key == "upload_dir" → cfg.upload_dir    │
        │    │ key == "username"   → cfg.username      │
        │    │ key == "password"   → cfg.password      │
        │    │ key == "auth_enabled"→ cfg.auth_enabled │
        │    │ иначе → игнорировать                    │
        │    └──────┬────────────────────────┘         │
        │           │                                   │
        └───────────┴───────────────────────────────────┘
                                (следующая строка)
```

## 6. Парсинг HTTP-заголовков — `parse_http_headers()`

### Описание

Реализована в `http_request.c`. Разбирает сырой HTTP-запрос из буфера и заполняет структуру `http_request_t`.

```c
typedef struct {
    char method[8];         // "GET", "POST"
    char path[128];         // "/", "/upload"
    char content_type[128]; // "multipart/form-data; boundary=..."
    char authorization[256];// "Basic YWRtaW46YWRtaW4="
    size_t content_length;  // тело запроса в байтах
} http_request_t;
```

Парсинг намеренно упрощён: `sscanf` с ограниченными шириной спецификаторами (`%7s`, `%127s`) — защита от переполнения буфера. Для поиска заголовков используется `strstr()`: нет нужды разбирать весь запрос, достаточно найти нужные подстроки.

### Блок-схема

```
    ┌──────────────────────────────────┐
    │           НАЧАЛО                 │
    │ parse_http_headers(buf, len, req)│
    └───────────────┬──────────────────┘
                    │
    ┌───────────────▼──────────────────┐
    │ memset(req, 0, sizeof(*req))     │
    └───────────────┬──────────────────┘
                    │
    ┌───────────────▼──────────────────┐
    │ sscanf(buf, "%7s %127s",         │
    │   req->method, req->path)        │
    │ → "POST", "/upload"              │
    └───────────────┬──────────────────┘
                    │
    ┌───────────────▼──────────────────┐
    │ h = strstr(buf, "Content-Length:")│
    │ если h != NULL:                  │
    │   req->content_length = atol(h+15)│
    └───────────────┬──────────────────┘
                    │
    ┌───────────────▼──────────────────┐
    │ h = strstr(buf, "Content-Type:") │
    │ если h != NULL:                  │
    │   sscanf(h, "Content-Type: %127  │
    │   [^\r\n]", req->content_type)   │
    └───────────────┬──────────────────┘
                    │
    ┌───────────────▼──────────────────┐
    │ h = strstr(buf, "Authorization:")│
    │ если h != NULL:                  │
    │   sscanf(h, "Authorization: %255 │
    │   [^\r\n]", req->authorization)  │
    └───────────────┬──────────────────┘
                    │
    ┌───────────────▼──────────────────┐
    │ return 0                         │
    └──────────────────────────────────┘
```
